# Skill Lifecycle Management System (SLMS)
**Ordem Estrutural Base para Ciclo de Vida e Segurança de Tools (Scripts de Inteligência Exógena) no Ecossistema Humano-IA SYNTROPY**

**ID do Protocolo:** `SLMS_LIFECYCLE_MANAGER`
**Nível Global:** Governança Orquestrada `SYSTEM_CORE`
**Versão:** 3.1
**Conformidade:** Relatório 08 / V3.1 

---

## 1. O PRINCÍPIO DO DESGASTE SISTÊMICO VIVO
Na biologia natural sintrópica, um órgão obsoleto atrofia. Na infraestrutura computacional modular (Agentes e LLMs plug-and-play), funções fixas obsoletas geram inchaço cognitivo e vetores de exploração maliciosa. Nenhuma Skill injetada via prompt ou external (MCP - Model Context Protocol) vive para sempre no estado inalterável.

Todo módulo ativado pelo Agente L0 deve orbitar dentro de um dos **Cinco Estados de Existometria**.

---

## 2. OS CINCO ESTÁGIOS VITALÓGICOS (A RODA DO SLMS)

### 2.1. INJECTED (Inoculada)
*   **Condição:** A Skill foi baixada (ex: `npx fetch_xyz`) ou criada pelo usuário. Ainda não rodou ativamente num workflow produtivo de inferência semântica.
*   **Controle de Acesso:** Exige Assinatura L1 (Hash Approval) e triagem pelo *Semantic Firewall* se a Skill comunicar dados pela rede P2P ou APIs terceiras (Princípio de Zero Trust Local Workspace).

### 2.2. ACTIVE (Ativa e Integrada)
*   **Condição:** Está na memória Hot do Agente L0. Está respondendo frequentemente a demandas (ex: `SKILL_COMUNICACAO_EMPATICA` que quase nunca degrada).
*   **Telemetria de Sobrevivência:** Tem a sua métrica validada diariamente ("Essa ferramenta resolveu eficientemente o que deveria sem causar gargalo de CPU ou Latência Contextual L0?").

### 2.3. DEGRADED (Degradada / Avisos Latentes)
*   **Condição:** O L1 notou que a Skill começou a tossir metadados. Ela entrega a resposta, porém as APIs terceiras mudaram de versão (excesso de deprecated warnings), ou o escopo do usuário mudou e ele a ignora frequentemente.
*   **Auditoria L0:** O Agente envia um relatório ao final do ciclo: *"Nosso módulo X está custando processamento e suas respostas estão lentas (ou as fontes caducaram). Sugiro revisar as âncoras destas diretivas"*.

### 2.4. DEPRECATED (Obsoleta / Isolamento Honroso)
*   **Condição:** A Skill perdeu 40% (Score Limits) de integridade ou o usuário atingiu um estágio (HDMM Nível H4) onde usar essa macro seria cognitivamente inferior à resolução orgânica do Humano.
*   **Gatilho Transacional:** O recurso entra em hibernação local. O L0 para de puxar o contexto ativamente (retirada da janela de RAM imediata) e passa a tratá-la apenas se invocada cirurgicamente com nome exato, guardando I/O. 

### 2.5. QUARANTINED (Quarentena Oblitória)
*   **Condição:** O *Semantic Firewall* ou L1 detectaram Injeção Ontológica Maliciosa dentro da Skill injetada, violação extrema das regras L4 (Tentativa de leitura de *Biometrics* fora da zona acordada ou violação agressiva de `SOUL.md`).
*   **Gatilho Reativo de Resgate:** Exclusão sumária ou Sandboxing Profundo sem acesso a nenhuma rede. É lançada uma tela encarnada ao Crivo Humano ("Vetor Malicioso estirpado às hh:mm por subversão das leis de proteção base da Sinergia").

---

## 3. RBAC SEMÂNTICO DE CARREGAMENTO (Controle Baseado em Roles Epistemológicos)
IAs externas invocadas ou injetadoras para um painel nunca possuem Nível "Deus".
*   *External Plugins* nunca leem o Kernel (O Root System). Eles enxergam apenas uma *Interface API de Dummy* cedida pelo Agente L0.
*   Operações Exógenas limitam sua *Output Window* e se assinam dentro da `MATRIZ_AICM` no quadrante respectivo, garantindo que mesmo uma habilidade invadida não poderá causar impacto contundente (N3/N4).
